# Writing Documentation

Guidelines for formatting and authoring Markdown documentation in this repository.

## Editorial Principles
- **Direct & Technical:** Use clean, professional language.
- **Visual & Structural:** Use tables, callout admonitions, and diagrams instead of walls of text.
- **Fact-based:** Document real implementation details. Do not invent metrics or benchmark numbers.

## Callout Admonitions Syntax
```markdown
> [!NOTE]
> Important context or implementation note.

> [!TIP]
> Optimization advice or best practice.

> [!WARNING]
> Potential issue or operational constraint.
```
